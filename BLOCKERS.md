## 3.5 — Anthropic API key rejected (401 invalid x-api-key) (RESOLVED 2026-10-10 01:30)

- **What it was:** Two stacked problems, not one. (1) `app/.env.local`'s real `ANTHROPIC_API_KEY` was being silently shadowed by a stale 10-character `ANTHROPIC_API_KEY` already set at the **shell environment level** (likely a leftover `export` in André's `.zshrc`/`.profile` from an older project) — `dotenv`'s default `config()` never overrides a var that already exists in `process.env`, so every script loaded the shell's placeholder instead of the real key. Diagnosed via a throwaway script that printed only the key's length/shape (never the value) to confirm the mismatch. Fixed by adding `override: true` to every script's `dotenv.config()` call (`check-env.ts`, `agents-smoke.ts`, `keys-export.ts`, `print-pubkeys.ts`) so `.env.local` always wins regardless of shell pollution — more robust than asking André to go hunt down the stale shell export. (2) Separately, once the real key worked, the "bold" agent still failed: `@anthropic-ai/sdk`'s `zodOutputFormat(...).parse()` **throws** on schema validation failure instead of returning a null `parsed_output`, so `run-agent.ts`'s `response.parsed_output ?? null` never ran — the "one repair retry" was dead code for the single most common failure mode. Fixed by wrapping the call in try/catch, returning a typed `{ kit } | { error }` result, and feeding the actual validation error into the repair prompt instead of a generic message.
- **Verified:** `npm --prefix app run agents:smoke` → 3/3 agents produce valid, referee-passing kits; the off-brief fixture correctly fails. `typecheck`/`build`/`lint`/22 unit tests all green.
